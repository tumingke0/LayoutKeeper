# 隔离开发候选：真实手动恢复与重连规划

> 0.4.0 起应用改名为 LayoutKeeper（原名 SpacePort）。本文中的 SpacePort、`SpacePort.app`、`spaceportctl`、`~/Library/Application Support/SpacePort` 等是当时的名称和路径，记录的是历史证据，未改写；现在分别对应 LayoutKeeper、`LayoutKeeper.app`、`layoutkeeperctl`（`spaceportctl` 仍为软链接）、`~/Library/Application Support/LayoutKeeper`。

最新受控跨桌面执行与空白验收入口见 [受控跨 Space 候选](CONTROLLED-CROSS-SPACE.md)。下文保留第一阶段默认同桌面路径的说明。

这份说明描述隔离源码的新增实现，不表示当前已授权的 0.1.1 应用已更新或已通过真实窗口验收。本轮不部署、不重签、不运行真实移窗测试。多 Spaces 与家/公司换屏恢复仍是目标；同桌面恢复只是第一步。

## 可复用与新增链路

复用 `WindowSelector`、`Planner`、归一化坐标、AX 窗口读取及普通桌面成员关系检查。新增 `MonitorRestorePlanner`、`ManualRestorer`、`RestoreJournalStore`、`VersionedStore`，简单模式接入“预览手动恢复”“查看恢复结果”“撤销上次恢复”。

1. 保存只读取当前可枚举的外屏普通窗口。再次保存先说明覆盖行为，保留原文件完整字节到同目录 `.previous.json`，再原子更新当前文件。备份失败就不覆盖。
2. 预览只读扫描真实窗口。记录按外屏硬件身份查找；保存的逻辑窗口组必须明确对应到本次连接的普通桌面。界面中的桌面顺序仅用于本次选择，不持久化或推断重连后的桌面意义。
3. 按 bundle ID 加文档标识匹配；缺少文档标识时仅用精确标题。未找到、重名、未知/多桌面成员关系、全屏、最小化及非普通窗口不会写入。多个保存窗口组不能合并到同一个桌面。
4. 同一普通桌面的项目允许手动确认位置和大小；跨桌面项目保留目标桌面与目标几何，显示待验证原因，禁止执行。目标显示器必须是当前唯一外屏。
5. 执行前复核会话、拓扑、窗口 token、进程启动时间、选择器、桌面和当前位置；创建新的本地操作日志并回读，再持久化写入意图。日志失败时不写窗口。真正写入前再次复核，防止快照期间用户调整被覆盖。
6. 每项操作后回读位置、大小和普通桌面。失败会停止后续项目，尝试按倒序回滚已尝试的窗口；无法回读或身份/拓扑/位置已变就停止该项回滚，明确报告失败。
7. “撤销上次恢复”仅处理本次会话中仍保持操作结果的窗口。用户后来移动、关闭、替换窗口或改变拓扑后跳过，不覆盖后续调整。日志保存在本机 `Layouts/transactions`；重启后不自动重放日志或恢复窗口。

固定安装路径标签改成“固定安装入口”，候选路径仍为“测试候选”。路径标签不证明功能完整。

## 多桌面和换屏规划层

已保存的窗口组不包含运行时 display、Space 或 window ID。重连后使用新会话、新显示器 token、新 Space ID 和新窗口 token 重新生成预览；同一硬件记录需要用户明确绑定当前桌面。桌面数量不足时显示缺口，不创建、删除、合并或猜测桌面。不同硬件使用各自屏幕记录；缺少序列号的同型号设备仍无法自动区分。

跨桌面规划保留 source 与 target 成员关系及目标 frame；当前真实执行器再次强制要求 source == target。不能用位置移动代替 Space 移动，也不会自动启动或重新打开未匹配的应用。

## 已通过的 fixture 桥接如何推广

`SPDispatchOwnedFixture` 当前只接受 `NSApp.windows` 中的 `SpacePort Fixture 1`，限制 27.0 / 26A428、主线程、普通非最小化窗口；检查私有方法 ABI，调用返回 0 仅表示派发。此前 `4 → 6 → 4` 只证明该构建上的单个自有窗口往返。

推广到真实应用前，至少需要一个独立、默认禁用的后端和集中实测：

- AX 元素 PID、CG 窗口所有者 PID、bundle ID、进程启动时间与 window ID 必须一致；每次写入前重新确认选择器唯一、窗口类型及单一普通 Space 成员关系。不能简单删除自有窗口保护。
- 源/目标 Space 必须在同一个已冻结会话和拓扑内，属于明确选定的显示器；未知、多个成员关系、全屏或拓扑变化时禁止派发。
- 限定已观察的 OS build 与 ABI，单窗口顺序派发；先验证目标成员关系达到且源成员关系消失，再调整几何，最后验证目标几何和成员关系。派发返回值不算成功。
- 完整保存源 Space 与原 frame；任何部分失败时只对仍保持身份及预期操作结果的窗口回到源 Space，再恢复原几何并验证。没有回读证据时不盲目回滚。
- 先指定新建的真实应用测试窗口，单独批准预览，再扩大到多窗口、跨显示器、显示器拔插。隔离候选现已增加逐窗受控派发入口，默认关闭；真实应用效果仍未实测，原 fixture 保护保留。

## 自动化验收与剩余实测

自动化采用内存窗口后端和临时目录，不读取或移动真实工作窗口。覆盖显式桌面绑定、重连 ID 变化、桌面不足、歧义与缺失匹配、未知/多桌面成员关系、预览过期、PID 复用、备份字节保留、日志失败、假成功回读、部分写入与批次回滚、撤销失败及用户后续调整。

仍需集中实测：授权 GUI 的真实保存读回、不同应用的尺寸限制和 AX 读取完整性、确认后的同桌面恢复与撤销、真实应用跨 Space 后端、跨显示器和拔插、自动重连后的桌面语义解析。当前没有自动恢复、桌面创建/删除/重排、Z 顺序或标签页恢复。
