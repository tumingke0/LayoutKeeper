# 使用说明（LayoutKeeper 0.5.0 build 11）

LayoutKeeper 原名 SpacePort。日常只用菜单栏：**保存当前布局 → 恢复布局 → 需要时撤销**。主窗口用来看状态和改屏幕名称。

## 首次使用引导（0.5.0）

第一次打开时出现三步引导（可以跳过；“设置 → 通用 → 启动 → 重新打开使用引导…”可再次打开）：

1. **权限**：说明为什么需要“辅助功能”。点“打开系统设置”时会弹出系统授权提示并打开“隐私与安全性 → 辅助功能”（macOS 27 上叫“设备控制和数据访问”）。**只有点这个按钮才会弹提示**（0.4.0 及以前从不弹提示；启动时和设置页里的“打开系统设置”也不会弹）。引导每秒检查一次授权，打开开关后自动打勾并进入下一步。
2. **开机自启**：开关默认打开，点“下一步”时通过系统的登录项（SMAppService）生效；需要你在“系统设置 → 通用 → 登录项”批准时会提示并给出按钮。设置 → 通用 → 启动 里也能随时开关。
3. **保存第一份布局**：接着外接屏时点“现在保存”（与菜单栏的保存相同，覆盖时保留上一版）；没接外接屏时可选“下次接上外接屏时提醒我”，之后第一次接上**还没保存过布局**的外接屏时，右上角会出现一次提示（带“现在保存”）。

之后每次启动，如果发现没有辅助功能权限（例如重新构建后），会只显示第 1 步。关闭引导窗口等同跳过。

## 菜单栏（主入口）

点菜单栏图标，从上到下：

| 项目 | 快捷键 | 行为 |
| --- | --- | --- |
| 灰色状态行 | — | “公司 · 7 个窗口 · 今天 09:42”；没接外接屏时“未连接外接屏”；还没保存过时“<屏幕名> · 尚未保存”。 |
| 保存当前布局 | ⌃⌥⌘S | 立即保存，不弹窗、不打开主窗口。覆盖时照旧保留上一版 `.previous.json`。右上角提示“已保存 N 个窗口”（约 2 秒），失败时提示原因。 |
| 恢复布局 | ⌃⌥⌘R | 立即生成计划并只执行能唯一确认的窗口（“需要确认”的绝不动），可撤销。完成后提示“已恢复 N 个窗口 · M 个需确认”，带 **撤销** / **查看**；“查看”打开独立的预览/结果面板。从另一块屏幕移回的窗口在这里会执行（自动模式不会）。 |
| 按住 Option：预览后恢复… | — | 打开预览面板，逐项查看并在面板里确认后才移动。 |
| 撤销上次恢复 | ⌃⌥⌘Z | 只有可撤销时出现。 |
| 接上屏幕时 ▸ | — | 关闭 / 先询问 / 自动（全局默认）。当前屏幕有单独记住的选择时，会多出“<屏幕名>：<选择>（已记住）”和“改回跟随上面的设置”。 |
| 暂停自动恢复 ▸ | — | 1 小时 / 直到明天；暂停中显示“自动恢复已暂停（至 HH:mm）▸ 恢复自动”。 |
| 打开 LayoutKeeper… | — | 主窗口。 |
| 设置… | ⌘, | 按住 Option 变成“高级工具…”（设置的“高级”页）。 |
| 退出 LayoutKeeper | ⌘Q | |

不能用的项目变灰，并在下面用小字写原因（“未连接外接屏”“需要辅助功能权限”“尚未保存布局”“正在处理上一个操作”）。

**全局快捷键**（设置 → 通用 → 全局快捷键）：默认 ⌃⌥⌘S / ⌃⌥⌘R / ⌃⌥⌘Z，用系统的 Carbon 热键接口注册，不需要“输入监控”权限。点按钮后按下新组合即可录制（Esc 取消），必须包含 ⌘、⌃ 或 ⌥ 之一；同一组合不能给两个动作。注册失败（通常是系统或其他应用已占用）会在该行显示“注册失败：可能已被系统或其他应用占用，请换一个”。可整体关闭，也可单独清除某一个，“恢复默认”一键还原。

## 右上角轻提示

不抢焦点、不挡操作的小面板，鼠标停在上面时不会消失。

- 保存：约 2 秒。手动恢复：约 5 秒。自动恢复：约 7 秒。
- **规则（固定）**：
  - 手动操作（菜单、快捷键、主窗口按钮）**总有反馈**；没有需要移动的窗口时提示“布局已是保存的样子”。
  - 自动恢复**什么都没动、也没有需要你处理的窗口时不提示**。有窗口被恢复、有窗口需要确认、或有窗口在另一块屏幕上被跳过时才提示；出错时给出黄色提示（这块屏幕本来就没有布局时不提示）。

## 接上屏幕时：每块屏幕只问一次

- 全局默认“先询问”时，**每块屏幕第一次**接上（且已保存过布局）会在右上角问：“以后接上「<屏幕名>」时自动恢复布局？” **[自动恢复] [每次先问] [不要]**。
  - 自动恢复：记住，并立即按自动流程恢复。
  - 每次先问：记住，这次照常弹出“检测到「<屏幕名>」”提示（恢复布局 / 这次不用 / 先预览…）。
  - 不要：记住为关闭。直接关掉提示框则什么都不记。
- 记住的选择按屏幕硬件身份（EDID 厂商/型号/序列号）存，**优先于全局默认**。可在菜单“接上屏幕时”里改回跟随默认，或在设置 → 通用 里逐个修改。
- 全局默认是“自动”或“关闭”时不提问，直接按默认处理。
- **自动恢复**没有对话框：先等屏幕稳定 3 秒，再读取已保存应用的窗口位置，**连续约 1 秒不变**（每 0.25 秒读一次，最多等约 5 秒）才开始；只执行无需确认、唯一匹配、且不是从另一块屏幕移回的窗口；完成后右上角提示（见上方规则），可撤销。
- 拔掉屏幕不做任何事。暂停期间（1 小时 / 直到明天）完全不提示也不恢复，等待中途开始暂停也会取消。

## 主窗口（按状态）

- 屏幕卡片是主角：屏幕名称（点铅笔可改成“公司”“家里”等，只存在偏好设置里，不改布局文件）、“保存于 今天 09:42 · 7 个窗口 · 3 个桌面”、每个桌面一个小方块（画出窗口位置和应用图标），支持跨桌面时右上角有一个低调的“支持跨桌面恢复”标记。
- **只有一个突出按钮**：
  - 还没保存：**保存布局**。
  - 和保存的不同：**恢复布局**（直接恢复，同菜单）+ 次要的“保存布局”，下面有“先预览，再恢复…”链接；卡片里写“N 个窗口不在保存的位置 · M 个需确认”。
  - 已经一致：绿色的“✓ 已是保存的布局”，“保存布局”为次要按钮。
  - “是否一致”由一次只读检查得出（不移动任何东西）：打开主窗口、应用被激活、切换桌面、屏幕变化、保存/恢复之后自动重新检查（有防抖；只在主窗口可见时进行，不会因为切换到其他应用而触发）。没有“将恢复”也没有“需要确认”的窗口即为一致；未打开或无法恢复的窗口单独列出。
- 底部一行状态：上次恢复时间和数量 + **撤销** 链接；需要权限时带“打开设置”。
- “接上屏幕时”的选择已移到菜单和设置里。

## 恢复预览面板

独立面板（菜单按住 Option、主窗口“先预览，再恢复…”、提示里的“查看”都会打开它）。

- 顶部汇总标签，**只有三种颜色**：绿色 = 将恢复 / 已恢复（每行副标签写“移到桌面 N”“调整位置”“从另一块屏幕移回”）；黄色 = 需要确认 / 未通过；灰色 = 已在原位、未打开、无法恢复（写原因）、已跳过。
- 需要确认的窗口始终显示在上面，带候选下拉框；其他所有窗口收在“查看详情（N 个窗口）”里，默认收起。
- 底部：重新预览、撤销上次恢复、关闭、“恢复 N 个窗口”（点一次即执行，这就是确认）。执行后每行显示结果。

## 设置

- **通用**：接上屏幕时（全局默认、每块记住的屏幕单独选择、暂停/恢复自动）、全局快捷键、跨桌面恢复状态、权限、关于（版本、数据文件夹、迁移结果）。
- **诊断**：一键自检、可保存窗口检查与统计、技术信息与导出。
- **高级**：按窗口组手动恢复、安全演示与空白窗口测试。

## 保存与恢复的细节

1. **保存**：读取外接屏所有普通桌面上能读到的普通窗口（不只当前桌面），记下应用、文档或标题、在第几个桌面、归一化位置和大小。不会移动窗口。再次保存保留上一版（`.previous.json`）。主窗口的“保存布局”按钮覆盖前仍会确认；菜单和快捷键直接保存（同样保留上一版）。
   - 布局按屏幕硬件区分，家和公司的屏幕各存一份，不用选地点。
   - 0.2.0 之前保存的布局没有“第几个桌面”，需要重新保存一次。
2. **恢复**：保存时的第 N 个普通桌面 = 现在这块屏的第 N 个普通桌面（按调度中心顺序，全屏应用桌面不计）。桌面不够时提示“请先在调度中心新建桌面”，不猜，也不替你新建。执行前重新读取窗口；跨桌面移动先回读确认到了目标桌面，再写位置和大小，再回读；失败的项目回滚。**撤销上次恢复** 把窗口送回恢复前的桌面、位置和大小（之后被你手动挪过的窗口会跳过）。

## 数据与迁移

数据在 `~/Library/Application Support/LayoutKeeper/`。第一次启动时若这里还没有屏幕布局，会从 `~/Library/Application Support/SpacePort/` 以及旧版从项目 `build-products` 运行时使用的项目内 `Layouts/` **复制**全部数据（布局、上一版、撤销日志、自检报告），逐个比对和解析校验后才启用，并写 `migration-from-spaceport.json` 标记；旧文件夹不动。偏好设置从旧 bundle ID 复制一次。

## 窗口怎么认（不猜，但够实用）

- 应用（bundle ID）必须一致。
- 普通应用：有文档路径（AXDocument）时只认文档路径；没有时认精确标题。
- 浏览器（Chrome、Safari、Edge、Arc、Firefox、Brave、Vivaldi、Opera）：不用网址作主键；标题先去掉开头的未读数“(3) ”和结尾的“ - Google Chrome”等，再比较。
- 有多个同名窗口时，用“保存时在第几个桌面”和“位置大小”（相差 3% 以内）挑出唯一一个；仍挑不出来就标“需要确认”，下拉框列出同应用的候选窗口（标题 · 桌面 · 尺寸），由你选，或选“本次跳过”。
- 浏览器标题变了、但同一桌面同一位置恰好有一个该浏览器窗口时，会预选它，但仍要你点“就是这个”确认。
- 一个当前窗口只能对应一条保存记录；冲突时两条都要你确认。
- 访达（Finder）等没有进程启动时间的应用无法通过身份校验，不能被自动移到别的桌面：预览里这一行直接显示“无法恢复”和原因，其他窗口照常执行（build 8 修复：之前这类窗口会让整批恢复失败）。同一桌面内调整位置和大小不受影响。

## 安全边界

- 不改 SIP/TCC/系统设置，不新建或删除桌面，不启动或退出应用。
- 跨桌面移动按运行时能力开启（见下方“系统版本支持”），每个窗口都先回读确认到了目标桌面，失败的项目回滚；不支持的系统只调整同一桌面内的位置和大小。
- 布局文件不含窗口 ID、Space ID 或显示器运行时 UUID；只有“第几个桌面”这样的序号。
- 撤销日志在 `~/Library/Application Support/LayoutKeeper/Layouts/transactions`，含本次会话的窗口身份和原始位置，只用于本地撤销。

## 系统版本支持（0.3.0 起）

不再写死某一个系统 build，而是启动时检测：系统 ≥ macOS 26，且 SkyLight 里存在跨桌面移动所需的私有接口（`SLSBridgedMoveWindowsToManagedSpaceOperation` 及其 `initWithWindows:spaceID:`、`performWithWMBridgeDelegate:`）和回读接口（`SLSCopySpacesForWindows`、`SLSCopyManagedDisplaySpaces`、`SLSMainConnectionID`）。检测只做符号查找，不调用移动接口。

| 系统 | 跨桌面恢复 | 同桌面恢复 / 保存 |
| --- | --- | --- |
| macOS 27.0 (26A428) | 开启，已通过一键自检 | 可用 |
| macOS 26.x / 27.x 其他版本，接口齐全 | 开启，界面轻提示“此系统版本尚未运行过一键自检”，建议到 设置 → 诊断 跑一次；每个窗口照常回读、失败回滚 | 可用 |
| macOS 26+ 但缺少任一接口 | 关闭，设置里列出缺少的接口 | 可用 |
| macOS 14 / 15 | 关闭：14.5 起旧的跨桌面接口已被系统拦截（yabai 也有同样结论），新接口从 macOS 26 才有 | 可用 |

找回非当前桌面窗口所需的私有符号缺失时，那些窗口会被计为“读不到”，不会报错，也不会影响当前桌面的窗口。最低系统仍为 macOS 14。

## 已验证 / 未验证

**已验证**（用户在 2026-10-10 22:59 运行的一键自检 `selftest-20261010-225904`，版本 0.1.2 (6)，macOS 27.0 26A428）：
- 采集：外接屏 4/4 个普通桌面上的 6 个可保存窗口，包括非当前桌面的 Chrome 窗口（通过远程令牌找回 2/2）。
- 真实 Chrome 窗口跨桌面移动（桌面 3 → 桌面 2）、撤销回原桌面、再次移动、最终复位，全部回读通过（C1、C2、C4、D）。
- 同桌面恢复（B）回读通过。

**自检同时发现**：在最大化的 Chromium 系窗口上，“先改大小再改位置”时大小写入没有生效（前台和后台桌面表现一致，所以不是后台桌面的问题）。0.2.0 已改为：变小时先改大小再改位置、变大时先改位置再改大小；写入期间临时关闭应用的 AXEnhancedUserInterface；回读不符时换一种顺序再试一次。自检的微调也改成“先缩小再移动”，并把后台写入（C3）与前台（B）对比，结果一致即算通过。

**用户实测（2026-10-11，0.2.0 build 8）**：一键恢复整条流程（预览、确认、跨桌面、撤销）在真实窗口上正常工作。

**尚未验证**：
- 0.4.0 的菜单栏直接恢复、全局快捷键、轻提示、只问一次、窗口稳定等待，以及首次启动的数据迁移在真实环境中的表现（单元测试覆盖，未在真实窗口上运行）。
- macOS 26.x 及 27.0 26A428 以外版本上的跨桌面恢复（会提示“未自检”）。
- 拔插屏幕 / 唤醒后的“只问一次”“先询问”提示和“自动”模式。
- 从另一块屏幕（如内置屏）移回外接屏的窗口（代码允许，但从未验证；自动模式不会执行这一类）。
- 两块及以上外接屏同时连接（目前只支持一块外接屏）。
