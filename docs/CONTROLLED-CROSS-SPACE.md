# 受控跨 Space 候选与一次集中验收

> 0.4.0 起应用改名为 LayoutKeeper（原名 SpacePort）。本文中的 SpacePort、`SpacePort.app`、`spaceportctl`、`~/Library/Application Support/SpacePort` 等是当时的名称和路径，记录的是历史证据，未改写；现在分别对应 LayoutKeeper、`LayoutKeeper.app`、`layoutkeeperctl`（`spaceportctl` 仍为软链接）、`~/Library/Application Support/LayoutKeeper`。

这份隔离候选新增了真实跨桌面执行代码，不只生成规划。当前已授权的安装应用未修改；本轮不签名、不部署、不运行真实移窗。编译和内存后端测试不能证明其他应用窗口或换屏流程已实际通过。

## 默认行为与批准范围

启动、显示器识别、布局读回、保存和恢复预览都不派发移窗。通用 `ReadOnlySpaces.canMove` 仍为 false。“本次启用受控跨桌面恢复”默认关闭，不保存为偏好；重新读取预览会清除开关和桌面映射。开启后仍须逐项预览并确认，才生成窗口专属许可。

许可冻结当前会话、拓扑、窗口 token、bundle/document/title、进程启动时间、源/目标 Space 和两个 display token。只允许这条正向路径及其原路回滚，不允许移动别的窗口或任意第三桌面。后端和许可只存在于已确认操作的内存范围。

`SPDispatchOwnedFixture` 的旧保护保留。新增 `SPDispatchVerifiedWindow` 验证当前 GUI AX 权限、主线程、精确 27.0/26A428、AX PID 和 window ID、进程启动时间与 bundle、精确选择器、普通非最小化/非全屏状态，以及 CG window owner。调用前再次检查单一源成员关系、源/目标普通桌面与 display，最后核对私有 ABI。没有隐藏地址扫描、注入或安全设置变更。

## 事务与失败行为

- 先保存原 Space、原 display、原 frame 和身份，写入并读回新的本地操作日志，再保存写入意图。
- 每项重新核对身份、唯一匹配、拓扑、源/目标桌面和当前位置；条件变化则不派发。
- 私有方法返回 0 仅表示派发。只有窗口成员关系读回为目标单一普通桌面后，才调整位置和大小；最终再次验证目标 Space 与 frame。
- 失败停止后续项目。对有有效写后回读且身份/拓扑/位置仍一致的已操作窗口，先回原 Space 并验证，再回原 frame 并验证。
- “撤销上次恢复”复用相同原路许可和检查。用户后续调整、关闭或替换窗口后，不覆盖其变化；回滚失败、无法回读或拓扑改变会明确报告，不能承诺所有失败都会自动恢复。
- 空/多成员关系以及未知第三桌面会停止操作。异步窗口管理可能暂时出现这些状态；没有有效回读时不会盲目派发回程。

布局文件只存逻辑窗口组和归一化几何，不存旧运行时 Space/display/window ID。操作日志包含本次会话的运行时标识，仅用于本地撤销；不跨重启自动重放。

## 换显示器与漏项

屏幕记录按厂商、型号和设备序列号选择；不同屏幕各自使用对应记录。序列号缺失时同型号设备不能自动区分，界面明确提示。连接变化后重新识别当前 display token 和普通 Space，用户明确把保存的逻辑组对应到当前桌面；旧绑定不复用，不自动创建/删除/重排桌面，也不把桌面数量不足的组强行合并。

采集只覆盖此次可枚举窗口。记录新增已读取但被排除的窗口数以及 AX 读取问题数（不是未读窗口总数）；界面提示其他桌面可能漏项。不用 CG 窗口数量证明 AX 完整性，也不把漏读统一归为权限问题。

## 空白窗口限定的验收入口

高级模式 → 演示 → 打开空白演示窗口 → “预览空白窗口桌面往返”。预览只读扫描本进程的单个 `SpacePort Fixture 1`，列出源 Space、同屏另一普通目标 Space 和原几何。确认后执行目标回读，再立即原路撤销并验证。失去自有窗口身份、唯一普通成员关系或本机 build 不匹配就停止。另有“重试撤销空白测试”，仍只接受该自有窗口。

普通启动不会运行验收。不要把这个入口或原先的 `4 → 6 → 4` 成功当成真实应用验收。

## 一次集中实测方案

在本轮自动化通过后，另行审阅冻结候选、签名及部署；保留当前正常安装应用和可恢复副本。部署与真实窗口测试没有在本轮执行。

1. 同一 GUI 只读核对自己的 AX 状态。首先运行空白窗口往返，验证源/目标/返回成员关系、原位置和日志；失败就停止后续扩大。
2. 只用用户明确指定的新建空白真实应用窗口（例如一个无文档的 TextEdit 窗口）。保存并读回，检查上一版未被丢失，核对漏项提示。由用户明确把该窗口组映射到另一个已存在普通 Space，再批准预览。
3. 检查 AX 与 CG owner、进程启动时间和 window ID 一致；确认目标成员关系达成，位置/大小回读通过；立即撤销并验证回源。任何拒绝、假成功或回滚失败都保留结果并停止，不扩展工作窗口。
4. 再测试两个指定空白窗口和受控失败：预览后关闭窗口、手动调整窗口、改变显示器连接。变化后应停止后续写入；不靠合成鼠标、注入或旧 ID 兼容路径补救。
5. 换另一款屏幕后确认选择该屏对应记录；重新列出 current Space 和显式映射。缺少记录、桌面不足、序列号歧义或未匹配窗口要显示缺口。验证完恢复原连接，不启用自动恢复。

主要未验收风险是：WindowManager 私有桥接对其他应用的实际效果、异步成员关系收敛、非当前桌面 AX 读取完整性、不同应用尺寸限制，以及拔插后的桌面语义。若该桥接对真实应用返回无效果，交付可用替代是明确报失败、保留手动桌面归位后的几何恢复与撤销；不绕过系统保护，也不无期限尝试其他私有路径。
